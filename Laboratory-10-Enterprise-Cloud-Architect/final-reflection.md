# Final Reflection — The Enterprise Cloud Architect

## Reflection

Looking back at our journey from Laboratory 1 to Laboratory 10, I can clearly see how much we have grown. I started as a beginner in learning basic Linux commands and following step-by-step guides. Now, for our final mission, we were tasked with designing, deploying, and securing a complete enterprise infrastructure entirely from scratch. Going from trainees to Enterprise Cloud Architects was challenging, but it was a really rewarding experience for me.

The biggest difference in this final mission was that there were no step-by-step tutorials. We had to rely completely on what we learned and on official documentation. First, we set up our own Ubuntu Server Virtual Machine using Oracle VirtualBox. We configured the network settings, like port forwarding for SSH and HTTP, so we could access the server from our host laptops. Next, we successfully deployed a multi-tier containerized app using Infrastructure as Code. We wrote a complete `docker-compose.yml` file to launch a WordPress web app linked to a MariaDB database. By using Docker persistent volumes, we made sure the database records would survive a VM reboot. Also, we set up a custom Docker bridge network so the containers could talk securely, keeping the backend database hidden from the outside world.

Security and automation were also big requirements for this project. To keep the server safe, we set up the Uncomplicated Firewall (UFW) with a strict Default Deny policy. We only opened the specific ports needed for remote administration (SSH) and web traffic. In addition, we wrote a custom Bash script that automatically backs up the MariaDB database, compresses it, and deletes old backups to save space. We made the script runnable using `chmod +x` and scheduled it using a Cron job. Because of this, the server can now back itself up automatically, which was exactly what the client wanted.

Honestly, this project pushed me of my comfort zones. At first, I wasn't sure if being a Cloud Architect was within the range of my personal interests because it felt very technical and overwhelming. However, overcoming the challenges—like troubleshooting network errors and fixing broken containers—made the whole process incredibly fulfilling. I realized that even if this specific role wasn't my original dream career, successfully building this complex system from the ground up with the team gave me a huge sense of accomplishment.

Ultimately, this semester has changed my understanding of cloud computing. In previous missions, I learned about different cloud models, containerization, firewalls, and automation. This final project brought all those concepts together into one working system for us. Above all, I learned that being a Cloud Architect is not just about technical skills, it is about good documentation and preparation. Creating a professional operational manual on GitHub ensures that anyone can understand, maintain, and troubleshoot the infrastructure we built.
