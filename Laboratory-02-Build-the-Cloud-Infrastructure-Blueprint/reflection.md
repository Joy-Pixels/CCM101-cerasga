# My Reflection

For me, networking is the most important cloud infrastructure component,
because it's what connects everything together. Compute and storage are
great, but without networking, none of the resources could talk to each
other or be reached by users. In other words, it's kind of like the
roads that connect all the different parts of a city.

Similarly, Linux supports cloud computing in a big way because most
cloud servers actually run on it. Since it's free, stable, and
lightweight, it's perfect for running on a large scale. Moreover, a lot
of cloud tools and commands are built around Linux, which is why knowing
how to use it is a basic skill for anyone working with the cloud.

In addition, technical documentation matters a lot before deploying
infrastructure because it helps everyone understand what's being built
and why. For instance, if something breaks later, good documentation
makes it easier to fix. It also helps other engineers pick up where
someone left off, instead of guessing how the system was set up.

During this activity, I learned new Linux commands like `lscpu`,
`df -h`, and `hostname -I` to check system information such as CPU,
storage, and network details. Furthermore, I learned how AWS, Azure, and
GCP offer similar services but under different names, and I practiced
building a simple cloud architecture diagram using Lucidchart.

Overall, my GitHub portfolio has improved a lot after this mission. I
now have organized folders with proper Markdown files, screenshots as
proof of my work, and clear documentation that shows what I did step by
step. As a result, it looks more professional than before, and it also
shows that I actually understand the work, not just that I finished it.
Ultimately, this mission helped me get more comfortable using GitHub as
a place to show my growth as a future cloud engineer.
