# Mission Reflection — Cloud Automation Engineer

## My Reflection

Moving from a traditional systems administrator to a Cloud Automation Engineer has been a great learning experience. Completing this final mission helped me understand how large companies manage their computer systems.

First, automation is critical when managing hundreds of cloud servers because doing everything by hand is too slow and people make mistakes. If an IT worker had to log into every single server to run updates or trigger backups, they would waste a lot of time. Therefore, by using Bash scripts and cron jobs, administrators guarantee speed, consistency, and standard setups across the entire system. This approach stops the risk of "configuration drift," which means a server deployed today is perfectly identical to one deployed six months ago.

However, automation can also be dangerous because it multiplies human mistakes. For instance, if there is a bad typo inside a script that is scheduled to run on 1,000 servers, the computer will quickly run that error on every single machine. Consequently, instead of breaking just one server, a single mistake can cause a huge, company-wide outage in a matter of seconds. Because of this, testing scripts in a safe environment and using version control are very important steps in cloud engineering.

In contrast to the deployment strategies in Mission 6, writing a Bash script was very different from creating a Docker Compose YAML file. Specifically, a Bash script is procedural; I had to write step-by-step commands to tell the computer exactly *how* to do a task. On the other hand, a YAML file is declarative; I merely listed the services I wanted, and Docker automatically figured out how to build and run the stack.

Furthermore, looking back at my GitHub repository from Laboratory 1 to Laboratory 9, my understanding of Cloud Computing has changed a lot. Before, I only knew the basics. Now, I have gained in-depth knowledge of different cloud infrastructures and types of cloud storage, which is helpful for choosing the right solution for a project. I also learned about major platforms like AWS, Azure, and GCP. What is more interesting to me is how applications are deployed using containerization and Docker. I also really enjoyed learning about security, firewalls, and automation. Above all, using KillerCoda was a game-changer because it made our work lightweight, and its tools were very useful. Besides, these missions enhanced my skills in creating Markdown files properly by following the right structure and contents.

Lastly, the role I enjoyed the most was the Cloud Deployment Engineer in Laboratory Activity 6, Mission 6. For me, I am interested in creating web and mobile applications in the future, so this mission piqued my interest about how applications are deployed by the use of containerization. It showed me exactly how modern apps are delivered to users safely and smoothly. I learned that a container packages an application with all its dependencies, ensuring it runs perfectly on any server. Furthermore, using Docker Compose was a great experience because I could write a single YAML file to launch multiple connected services, like a web server and a database, all at once. Ultimately, this mission taught me that deployment is just as important as writing the code itself, bridging the gap between a developer's laptop and the real world.
